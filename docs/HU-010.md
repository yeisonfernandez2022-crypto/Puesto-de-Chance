## Historia de Usuario

> **Como** administrador del puesto de chance,
> **quiero** que cada acción de la API solo esté disponible para el rol autorizado,
> **para** proteger la operación (un vendedor no puede crear sorteos ni un admin vender tiquetes).

## Criterios de Aceptación

- [ ] Toda ruta protegida exige cabecera `Authorization: Bearer <token>`; sin token responde **401**.
- [ ] Un token inválido o expirado responde **401** ("Token inválido o expirado").
- [ ] Si el usuario del token no existe o está inactivo responde **401** ("Usuario no válido").
- [ ] Acceder a un endpoint de otro rol responde **403** ("No tiene permisos para esta acción").
- [ ] El rol viaja firmado dentro del JWT y no puede alterarse desde el cliente.

## Matriz de permisos

| Acción | ADMIN | VENDEDOR |
|---|:---:|:---:|
| Crear sorteos / registrar resultados | ✅ | ❌ |
| Vender y pagar tiquetes | ❌ | ✅ |
| Anular tiquete propio o ajeno | ✅ (cualquiera) | ✅ (solo propios) |
| Consultar sorteos, tiquetes y caja | ✅ | ✅ |
